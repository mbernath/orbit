# Architecture debt

Known shortcuts, taken deliberately for speed. Each entry names what is wrong, why it was accepted, and the **trigger** that makes it due. When a trigger fires, the fix is proposed as its own step before the feature that fired it.

Remove an entry when it is fixed; do not keep a history here (git has it).

| # | Debt | Why accepted | Due when |
|---|---|---|---|
| 1 | SSE only signals "changed"; the board then reloads the whole `/api/state` — now including the content of pinned files (up to 256 KB each). | Small state, simple and correct. | When `/api/state` exceeds ~1 MB or ~500 entities, or a live session view streams tokens — then send entity deltas. |
| 2 | `readAiTitle` and `lastAssistantText` read the whole transcript on every prompt and stop. | Files are local; titles matter. | With the live session view (tail-follow the file instead), or a transcript over ~20 MB in practice. |
| 3 | Elements belong to an island by their workspace, not by `parent`; frames are stored as `frame:<workspace>` elements with geometry only. | One island per workspace, no nesting yet. | When islands should nest, or an agent should place elements into a frame explicitly. |
| 4 | Session ↔ PR linking uses `git:<git_root or cwd>#<branch>`; imported sessions without `git_root` only link when their cwd is the repo root. | Hook sessions always send `git_root`. | When cloud workers or files need the same linking — then derive the repo root for imported sessions too. |
| 5 | Element sizes come from the view; `w`/`h` in `elements` are only used by frames, so documents cannot be resized. | Fixed sizes were enough to start; slice 2 replaces cards by dots anyway. | When the user asks to resize, or a second document-like view (live session) needs more room. |
| 7 | `event_log` grows without limit. | A few thousand rows a day. | When `orbit.db` passes ~100 MB — then add retention. |
| 8 | The file picker walks the workspace folders on every open (capped at 2,000 files, depth 6). | Fast enough for current workspaces. | When opening the picker takes over ~300 ms, or a workspace hits the cap. |
| 9 | The Markdown editor is a plain textarea; checkboxes in the rendered view are read-only. | Enough for roadmaps and notes. | When the user edits files on the board often — then toggling tasks in the rendered view, or a proper editor (ADR). |
| 10 | Browser tests share one server per Playwright project, files run in name order. Project `board`: one filled fixture (`1-reading` expects it fresh, `2-islands` changes geometry, `3-detail` changes data; the fixture pins its document after the server already answers; it presets every first-run hint as retired and installs the hook in its Claude settings). Project `first-run` (ADR-0041): a second server with an empty data folder at a fixed temp path (`test/e2e/onboarding/`), its three tests build on each other in one file. | Two servers keep the suite fast; the second was the cheapest way to an empty fixture. | When a third fixture is needed, or order starts to bite — then a reset route for tests or one server per file. |
| 13 | Undoing "Insel entfernen" re-adds the workspace through `workspaces.add` with its name and **first path only**; extra paths are lost, and the id changes if the name's slug is taken meanwhile. | Islands with several paths are rare; removal is only possible for empty islands. | When an island with several paths is removed in practice — then a `workspaces.restore` action that takes the whole entry. |
| 16 | After an Orbit restart, a pending permission request of an owned session is lost (the process is gone); the session shows "unterbrochen" and continues on the next message. | Restarts are rare; resuming is safe. | When restarts with open requests happen in practice — then keep the request and re-ask after resuming. |
| 17 | An owned session only shows on the board once the Claude Code hook reports it (the `control` entity has no view of its own). Without installed hooks it runs invisibly. | Orbit installs the hook (`scripts/install-hooks.ts`); variant A keeps sources apart. | When someone runs Orbit without the hook, or the hook fails for owned sessions — then a session view for a `control` without a related session. |
| 18 | Space opens the reply field in the detail panel; replying directly in the bubble (elements.md depth "r") is not built. | The panel covers the need; the bubble reply needs its own layout work. | When the user replies often from the board without wanting the panel. |
| 20 | Worktrees go to `<repo>/.worktrees/<slug>`; Orbit does not touch `.gitignore` or `.git/info/exclude`, so the folder shows as untracked in the main checkout unless the repo ignores it. | Orbit never edits repo files on its own. | When it shows up in a repo the user works in — then offer once, on a click, to add `.worktrees/` to `.git/info/exclude`. |
| 21 | "Worktree auch entfernen" exists only for worktrees Orbit created (owned source); a worktree a session entered by itself is shown but not offered for removal. Removal keeps the branch `feat/<slug>`. | Removing worktrees Orbit did not create is riskier; branches may carry unmerged work. | When the user asks to clean up worktrees of observed sessions, or stale `feat/` branches pile up. |
| 22 | An agent counts as running until the hook reports its run's `session.done`; without the hook it stays blocked for up to 2 h (`RUN_TIMEOUT`). | The hook is installed with Orbit; the timeout keeps a lost signal from blocking forever. | When an agent is seen blocked in practice — then also clear the run when its owned process ends (a domain event from the owned source). |
| 23 | The agents source writes the memory file itself (create once, never overwrite) instead of through the files source. | Creating a file is not an action the files source offers; pinning does go through `ctx.act("files.pin")`. | When a second source needs to create Markdown files — then a `files.create` action with the same path limits. |
| 24 | A waiting question now overlays names and dots of its own island when it finds no free spot, but still stays hidden until hovered when every corner would touch another bubble, an island name, another island, chrome or the screen edge (the orange dot and the edge hint still show it). What it covers is not dimmed. | Rare (several questions crowded at a screen edge); hovering always shows it. | When the user misses a question in practice — then let a question push lower-priority bubbles aside and dim what it covers. |
| 25 | PRs without a session show only as the pill beside the island's "+" (ADR-0038); they are not part of the atlas level, the minimap, the edge hints or W/Q, because they have no element. | The pill sits where the user looks first; it needs no new element kind. | When the user misses such a PR from far out or while stepping with W/Q — then let the attention set take PR pills as places at the island's name. |
| 26 | Attachments stay in `~/.orbit/attachments/<session>/` forever; nothing cleans them up. | Few and small so far; deleting the user's files on a timer would be surprising. | When the folder passes ~1 GB — then offer cleanup of sessions taken off the board, on a click. |
| 27 | Attachments are offered only for owned sessions (reply field, new session), not for agent runs or the agent panel. | They were requested for the chat with a session. | When an agent needs input files — then the same `attach.js` in the agent panel's "Run now". |
| 28 | A message shown as "wird gesendet" is confirmed only when the transcript holds it; if Claude Code writes no transcript, it stays marked until the panel is reopened. | Real sessions always write a transcript. | When a pending mark is seen to stick — then confirm on the owned process's echo (`--replay-user-messages`). |
| 29 | A merge Orbit did not see (Orbit was off when the PR left the open list for good, or gh failed then) is not remembered; that session does not read as done. | Orbit usually runs; the detection covers merges from the board and from elsewhere while it runs. | When the user misses a done mark in practice — then ask gh once per session branch for a merged PR (`gh pr list --state merged --head <branch>`). |
| 30 | `web/js/main.js` is at 300 lines (guideline ~300). | Wiring only; the last additions were one-line handlers. | Before the next handler in main.js — move the generic click handlers (`data-action`, `data-dialog`, `data-remove`, island menu) into `clicks.js`. |
| 29 | The hook sends in the background, so two events of one session can arrive out of order within milliseconds (e.g. a late `PostToolUse` after the next permission notice), briefly showing "arbeitet" instead of "wartet". | Claude must never wait for Orbit, and `PostToolUse` fires on every tool step. | When a missed question is traced back to this — then send the hook's own timestamp and let the claude source ignore older events. |
| 31 | `src/sources/owned/index.ts` is at 320 lines (guideline ~300). | ADR-0028 added a few lines to `owned.answer` and the entity. | Before the next action or entity field in the owned source — move the action definitions into `actions.ts`. |
| 32 | Below the far zoom dots shrink with the glyph scale (ADR-0033), and so does their hit area; at very small zoom a dot is a few pixels to hit. | Zooming that far out is for overview, not for clicking. | When the user misses dots at small zoom in practice — then a minimum hit area through a transparent outline. |
| 33 | Elements without an island (pinned files outside every workspace, `__none__`) are drawn at world 0,0 — inside or over whatever island sits there; a ⇧-rectangle over that island selects them too (seen in the browser tests). | Pre-existing; noticed while building the selection (ADR-0034). | When the user pins a file outside their workspaces — then give such elements their own place (a "Lose" island or the free space beside the islands). |
| 34 | The browser tests' orbit island grows with every owned session the suite starts; tests that click a dot must bring it on screen themselves (9-panel pans, 95-arrange uses a taller window). | Cheap fixes inside the tests. | Together with #10 — when a test needs a fresh fixture, a reset route would remove this too. |
| 35 | A list script that hangs is abandoned after 30 s, not killed: the `Runner` has no timeout or kill, so the process may linger. | Scripts are the user's own and normally quick. | When a hanging list script is seen in practice — then a timeout in the `Runner` contract (core change, ADR). |
| 36 | A list command is not re-checked when the script file changes; configuring it is the only consent (ADR-0036). | The user configures every command themselves, in their own repos. | When lists come from repos the user does not control — then remember the script's hash and ask again on a change. |
| 37 | The board imports the list types from `src/sources/lists/contract.ts` instead of `src/core/types.ts`. | The list document is the script contract of one source, not a core contract. | When a second source or the core needs these types — then move them to `types.ts`. |
| 38 | Taking a list off the board deletes its configuration; undo pins it again as a new node (new id), so its position on the board is lost. | Lists are pinned rarely; undo restores the content. | When the user misses the position after an undo — then archive the element instead and delete only on an explicit "Remove". |
| 39 | Stream fixtures in `test/fixtures/claude-stream/` are recorded from the real CLI and carry the recording machine's environment in the `system/init` line (connected MCP servers, tool names, plugins, skills, agents). Existing fixtures were scrubbed by hand (MCP servers and `mcp__*` tools removed). | Recording is rare; a hand scrub was enough for two files. | With the next recorded fixture — then a small scrub step (script or `replaySpawner` loader) that empties `mcp_servers` and drops `mcp__*` tools, plus a test that fails on non-neutral init data. |
| 40 | The PR stack menu (`web/js/pr-stack.js`) positions itself at its chip with its own copy of the island menu's placement (clamped left, below the anchor) and its own outside-click and Esc handling. | Two small menus; a shared helper for two copies was not worth it yet. | With the third menu at a control — then a `menu-at.js` helper (place, close on outside click and Esc) used by all of them. |
| 41 | The stack at a session (several open PRs, ADR-0038) is covered by unit tests of `sessionPrs` and by the island's browser test of the shared `pr-stack.js`, but no browser test shows it at a session: no fixture session carries two branches with PRs. | The drawing and the menu are the same code as at the island. | When the session chip or its stack changes — then a fixture session that switched branches, with two open PRs in the gh stub. |
| 42 | Behaviour hangs on error wording: `src/sources/files/preview.ts` picks 404 by comparing the error text "File not found.", and `web/js/panel-doc.js` detects a save conflict with `/has changed/`. | The English translation kept both in step by hand. | When either message is reworded, or a third place matches error text — then error codes on the result (`Checked`, action errors) and match on those. |
| 43 | Recorded stream fixtures (`test/fixtures/claude-stream/*.jsonl`) still hold German prompts and replies, and `owned.test.ts` / `owned-ask.test.ts` assert them; the legacy `[Titel: …]` marker has no unit test any more. | Re-recording costs real CLI runs; the content is test data, not product text. | With the next re-recording (see #39) — record in English, and add a test for the legacy title marker. |
| 45 | "This week" (7 days) is defined twice: `RECENT_MS` in `src/sources/claude/folders.ts` (counts transcripts by file time for the suggestions) and in `web/js/import-choice.js` (keeps sessions by `updatedAt` on the first island). The keep step also briefly renders all imported sessions before archiving the older ones. | The board cannot import server constants; one number, two places, both next to ADR-0041's amendment. | When the window or the cap becomes a setting, or the flash is noticed — then an import option on `workspaces.add` / `claude.import` that marks older ones archived server-side, which needs a core contract change (ADR). |
| 46 | `web/style.css` is ~600 lines in one file, twice the ~300-line signal. | No build step; one stylesheet was simplest. | Before the next sizeable style change — then split by UI area (board, panel, menus, onboarding) into files linked from `index.html`, as its own step. |
| 47 | `hints.js` decorates elements other modules render (halo class on dots, "+", zoom dots) and re-applies it after every layout. | One module, small; keeps all onboarding in one place. | When a second module starts decorating others' elements this way — then a small decoration hook in `render.js`. |
| 48 | The auto-layout slot memory (`web/js/slots.js`) lives in the browser (`localStorage` `orbit.slots`), not on the server: another browser, or cleared storage, closes the holes in creation order on the next load (dots move once). The one-time tidy after the list layout (`web/js/tidy-once.js`, `orbit.tidy-once`) is per browser too: it runs again in every new browser or after cleared storage. | No core change for step B; an auto dot must stay distinguishable from a moved one, so writing its position into the element geometry was not an option. | When the board is used from a second browser, or a user reports dots that moved after a reload — then a core field for slot indices (ADR). |
| 49 | `test/e2e/4-owned.e2e.ts` "Text on the canvas cannot be selected by accident" failed once in four runs after the list layout (it reads the first `.lab-t`, which may now be a different label). | Passed on rerun; not investigated yet. | When it fails again — then make it target a specific session label and check for a timing dependency. |
| 50 | `test/e2e/99-tidy.e2e.ts` "An island with a waiting question: the question shows, nobody moves" fails in half or more of the full runs (its question bubble is not placed, class `sb` missing) — also on the commits before ADR-0042 and before the main.js split (4 of 4 there). | Passes alone and on rerun; a layout timing, not a product bug seen in use. | When it blocks a commit twice, or a user sees a waiting question without its bubble — then wait for the layout pass in the test, or find the race in `board-layout.js`. |
| 51 | `web/js/key-table.js` says which keys the board shows; `keys.js`, `panel-size.js` and `panel-owned.js` handle them. A key in the table without a handler is caught only by a browser test for that key (⌘⇧S has one). | Moving the handlers into the table is a larger refactoring than ADR-0043 needed. | When the overview names a key that does nothing, or a third module starts handling keys — then drive the handlers from the table too. |
| 52 | `scripts/readme-media/demo-board.ts` copies the shape of the e2e fixture (`test/e2e/serve.ts`): the stubbed git/gh runner, the hook poster with git headers, the action poster. Nothing checks that the README pictures still match the board. | Tests and pictures want different data; a shared fixture builder was more than one README needed. | When either fixture's runner stub changes for the same reason twice, or a README picture is noticed out of date — then a small fixture-builder module both use, and `bun run media` before each release. |
